# 人机验证处理

人工验证弹窗与请求恢复功能已移除。遇到豆包官网人机验证时，客户端会收到 `verification_required` 错误。网关不会额外打开验证窗口、恢复最小化窗口、将浏览器置前或等待人工处理，也不会自动重发被拒绝的请求。

## 请求与登录

- 上游 HTTP 验证拒绝和流式响应中的验证错误均直接返回客户端。
- 模型目录、额度查询和账号检测遇到验证拒绝时同样返回错误。
- 验证 challenge、Cookie 等内部数据不会出现在公开错误中。
- 普通请求超时仍由 `DW_TIMEOUT_MS` 控制，没有额外的人工等待期限。
- 正常对话和上游历史隐藏仍按原配置执行；验证失败不触发账号会话更新。

如果需要更新登录，可在管理台主动点击“添加账号”，或运行 `npm run login`。该操作会打开正常登录窗口。按官网流程完成扫码、手机验证码及官网自身要求的验证，确认接入后再发起新请求。

管理台“接入配置”显示“人机验证：返回验证错误”，不再显示人工等待时间。登录进度页面使用正常登录状态，不显示额外的“等待人工验证”状态。

## 旧配置与兼容性

旧的 `DW_AUTO_CAPTCHA` 和 `DW_CAPTCHA_*` 网关启动配置已停用。即使旧配置中 `DW_CAPTCHA_MANUAL_FALLBACK=true`，也不会启用验证弹窗或请求恢复。配置样例不再列出这些选项。

历史 `verification.mjs` 导入入口保留为停用的兼容接口：恢复调用直接抛出原错误，API 包装入口返回原 API，不创建浏览器或修改账号。

历史识别源码可以随源码发布。已安装的 `.captcha-venv` 和本地模型只保留在本机运行目录用于独立实验，网关与浏览器登录不加载它们。

## 验证

- `npm test` 覆盖旧配置不能恢复弹窗、验证错误直接返回、不重发请求、登录不置前窗口及正常账号导入。
- `npm run check`、`npm run check:admin` 和 `npm run check:captcha` 检查相关源码语法。
- 管理台与登录门户使用本地模拟验证状态检查提示移除及正常登录、取消交互，不需要触发真实验证码。
